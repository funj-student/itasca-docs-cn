方法

本构模型的基类

FLAC3D 对用户编写本构模型的支持利用了 引言（Introduction） 中所述的面向对象编程方法。 基类为实际的本构模型提供了框架，实际本构模型是从该基类派生的类。 该基类称为 ConstitutiveModel，是一个“抽象”类。它声明了若干“纯虚”成员函数（通过在函数原型后附加 =0 语法来表示）。 这意味着不能创建该基类的任何对象，并且任何派生类对象必须提供真实的成员函数，以替换 本构模型（ConstitutiveModel） 的每一个纯虚函数。

ConstitutiveModel 的完整文档见 程序员接口（Programmer’s Interface）。请参见 models 命名空间。

成员函数

任何派生的本构模型类都必须提供实际函数，以替换 ConstitutiveModel 中的虚成员函数。

模型类定义还应包含一个必须调用基类构造函数的构造函数。 在所有情况下，派生类构造函数都应以无参数方式调用，如 clone 成员函数所示。 数据成员的初始化可由构造函数完成，如此处所示。 在本示例中，符号 bulk_、shear_ 等是派生模型的数据成员。

典型模型构造函数

    ModelExample::ModelExample(unsigned short option) : ModelElastic(option) {
    }

模型注册

每个用户编写的本构模型都编译为一个 DLL，并且必须在 FLAC3D 进程中实例化。 按照约定，作为 FLAC3D 插件使用的 DLL 中有四个导出函数：getName()、getMajorVersion()、getMinorVersion() 和 createInstance()。 还必须提供一个名为 DllMain() 的桩函数，它在库从系统中加载和卸载时被调用。 例如，这些函数在 Example 模型中的形式如下：

int __stdcall DllMain(void *,unsigned, void *) {
    return 1;
}

extern "C" EXPORT_TAG const char *getName() {
#ifdef MODELDEBUG
    return "cmodelexampled";
#else
    return "cmodelexample";
#endif
}

extern "C" EXPORT_TAG unsigned getMajorVersion() {
    return MAJOR_VERSION;
}

extern "C" EXPORT_TAG unsigned getMinorVersion() {
    return UPDATE_VERSION;
}

extern "C" EXPORT_TAG void *createInstance() {
    models::ModelExample *m = new models::ModelExample();
    return (void *)m;
}

EXPORT _TAG 宏表示这些函数应从 DLL 导出。

DllMain() 函数始终相同。

导出的 DLL 函数 getName() 应始终返回以“cmodel”开头的字符串。 这表明该 DLL 是本构模型插件。 在上例中，导出的 DLL 函数 getName() 返回字符串“cmodelexample”。 ConstitutiveModel 类的 getName() 方法返回字符串“example”（名称前不加“cmodel”前缀，而导出的 getName() 函数则带有该前缀）。 应遵循在导出名称前加“cmodel”前缀的约定。 ConstitutiveModel 的 getName() 函数必须返回唯一字符串（这是用于区分各本构模型的方法）。

不应改动 getMajorVersion() 函数。 主版本号由基础本构模型 DLL 确定， 并表示二进制兼容性。 按照约定，该编号也会体现在您所生成的 DLL 的文件名中。

getMinorVersion() 函数表示本构模型的次版本更新。 例如，若向本构模型添加了新属性， 它可能与旧版本在保存文件上不兼容。 在这种情况下，次版本号（定义于文件 “version.txt”）将增加 1。

createInstance() 函数实际创建并返回您所定义类的一个实例。 该实例存储在注册表中，并（通过 clone() 函数）用于创建所有其他实例。

循环计算过程中模型与程序之间传递的信息

FLAC3D 与用户编写模型之间最重要的联系是成员函数 run(UByte d, State *ps)，它在计算循环中计算模型的力学响应。 一个结构体 State（在“state.h”中定义）用于向模型传入信息以及从模型传出信息。

State 的完整文档也见于程序员接口文档的 models 命名空间中（可在屏幕上的 Help 菜单中查阅）。

成员函数 run() 的主要任务是由应变增量计算新的应力。 在非线性模型中，传递模型的内部状态也很有用，以便绘制和打印该状态。 例如，随附的模型会表明它们当前是否正在屈服或过去是否曾屈服。 每个子网格都可以设置变量 state_，它以一系列可取开或关（1 或 0）的位记录模型的状态。 每一位都可以关联一条显示在屏幕上的消息。 成员函数 States 返回的字符串包含若干子字符串，分别对应于模型在 state_ 中可能置位的位。 第一个子字符串对应位 1，第二个对应位 2，依此类推。 可以同时置位多个位。 例如，剪切屈服和拉伸屈服可能同时发生。 位的分配如下所述。 查阅任一非线性模型文件（例如“modelexample.cpp”）即可理解状态逻辑的运作方式。

由于一个网格单元中的所有四面体共享同一个 ConstitutiveModel 实例，模型中的每单元状态信息只应在处理完最后一个四面体之后更新。State 结构包含有助于模型判断此点的信息。成员变量 sub_zone_ 包含当前正在处理的四面体（从 0 开始）。成员变量 total_sub_zones_ 包含该网格单元中来自所有叠合层的四面体总数。成员变量 overlay_ 将为 1 或 2，表示该网格单元中存在多少个叠合层。

此外，数据可以在同一网格单元内各四面体的多次调用之间保存，以供最后一次调用使用。数组 working_ 和 iworking_ 允许在给定网格单元的多次调用之间将数据安全地存入 State 结构。请注意，用户不应假定这些数组在首次调用第一个四面体时已初始化为零，而应自行检测并初始化该存储。

网格单元的状态指示符

FLAC3D 中的网格单元由四面体子网格组成——普通六面体网格单元中有两个各含 5 个四面体的叠合层，共 10 个四面体。每个四面体共享一个 ConstitutiveModel 类实例，但各自保有自己的状态指示符。 该成员变量有 32 位，最多可表示 16 种不同状态（假定分别跟踪“当前”和“过去”）。 内建本构模型使用状态指示符位来表示网格单元中四面体的塑性破坏。 位分配及内建本构模型对应的破坏状态见 表 1（Table 1）。请注意，这仅是一种约定，并非所有本构模型都实际需要。

tension_past = 0x0008 8 0000 0000 0000 1000

joint_tension_now = 0x0020 32 0000 0000 0010 0000
joint_shear_past = 0x0040 64 0000 0000 0100 0000

对于用户定义的本构模型，用户可以创建一个命名状态并为该状态指定任意特定位，随后更新四面体状态指示符变量。 表 1（Table 1） 中的命名状态被内建本构模型用于更新四面体子网格的破坏状态，并展示了状态指示符变量的一种特定用法。

表 1（Table 1） 中的命名状态被许多内建模型用于更新四面体子网格状态指示符。

FLAC3D 对构成网格单元的每个四面体调用本构模型函数 run()，以更新其应力值。 通常，本构模型在此过程中还会更新状态指示符。 对于内建模型，状态指示符表示四面体的破坏状态。 本构模型通过将四面体状态指示符变量与其计算出的当前破坏状态进行逻辑“或”（|）运算来更新该指示符。 用户应注意适当地置位或清除在本构模型计算当前状态之前更新的所有先前状态。 随后可使用逻辑“与”（&）运算符将状态变量与所需的用户定义状态进行运算，以检查四面体的状态。

假设某四面体正发生拉伸和剪切破坏。 该破坏状态存储在四面体的状态指示符中。 内建本构模型更新状态变量的方式如下：

  1. 首先检查当前状态，并相应地设置/取消设置状态指示变量。例如，
        if (s->state_ & shear_now) s->state_ |= shear_past;
        s->state_ &= ~shear_now;
        if (s->state_ & tension_now) s->state_ |= tension_past;
        s->state_ &= ~tension_now;
  1. 计算四面体的当前状态。
  2. 必要时更新状态。例如，
        s->state_ |= shear_now;

上述运算的结果是，该特定四面体的第 1 位和第 2 位被置位。 此外，在初始化（步骤 a）期间，第 3 位和第 4 位也被置位。 FISH 函数 单元状态（zone.state） 返回值 15，即前四位均置位所对应的十进制值。

用户可以使用 FISH 逻辑函数 单元状态（zone.state） 查明分析中任意点处的破坏状态。 用户还可以将输出拆分为二的幂之和，并查明所有不同的破坏状态。 例如，若 单元状态（zone.state） 返回 15，则 15 可写为 15 = 1 + 2 + 4 + 8（二的幂之和），并且由 表 1（Table 1） 可知，该网格单元正处于剪切和拉伸破坏，且过去曾发生剪切和拉伸破坏。
