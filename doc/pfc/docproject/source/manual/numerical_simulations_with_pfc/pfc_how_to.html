… 设置模型域

模型域（model domain）是一个与坐标轴对齐的长方体，它界定了 PFC 模型所在的空间。用户必须 在创建任何模型组件实例之前指定域的范围和边界条件。此步骤通过 设置模型域命令（model domain） 命令完成，该命令接受两个关键字：extent 和 condition。extent 关键字 用于分别沿每个全局坐标系方向指定模型域的范围。域的范围是固定的， 除非用户进一步修改。当模型组件分散时，域不会自动扩展。相反，它规定了 模型组件到达域边界时应遵循的行为；这些组件可以被销毁、停止、反射， 或在相对的域边界处周期性地重新插入模型中。该行为通过 condition 关键字设置。

请注意，stop 或 reflect 模型域边界条件不应与力学边界条件相混淆。它们并不对模型组件施加 任何力学条件，而是约束其运动学行为以符合给定的约束。 例如，若一个在重力荷载作用下沉降的球颗粒在激活 stop 条件的情况下到达域边界，它实际上会被停止， 但永远不会达到力学平衡，因为它所受到的唯一作用力就是自身重量。 因此，通常建议在模型域内使用物理边界条件（参见下面的条目（item below））， 除非需要采用周期性边界条件。

… 清理模型及其适用场景

我们将“干净”模型定义为这样一种 PFC 模型：其映射到 单元空间（cell space） 中的片体、片体之间的接触、接触的活动状态以及派生属性均为最新。 清理模型对象命令（model clean） 命令是一条全局命令，可在任何时候（循环序列之前或之中）发出，以确保模型处于干净状态。 用户可能希望使用此命令，主要有三个原因：

  1. 循环计算之前，模型创建期间： 创建模型组件时，它们可能不会自动映射到单元空间中，接触也不会自动创建。 相反，这些步骤会在第一个循环序列的最开始处首次强制执行。此后，每个片体都可能根据其累计位移在 单元空间中重新映射，并更新其接触列表。将接触检测与模型创建解耦，可以带来快得多、交互性更强的用户体验。 然而，视所设计的模型而定，可能需要在循环计算之前便将片体映射到单元空间并创建接触。 例如，如果模型组件的初始位置使得本应已经存在活动接触，并且希望 修改默认的接触属性（例如 bond select 接触），那么首先必须清理模型。其他操作（例如 使用 包围盒内球体（ball.inbox） 或 包围盒内刚性团簇（clump.inbox） 函数进行空间搜索）也同样依赖于映射到单元空间中的片体保持最新。
  2. 恢复模型状态之后： 模型状态刚恢复后，部件不会在单元空间中重新映射，以确保接触列表（包括非活动接触）与保存模型状态时所使用的接触列表完全对应。 基于上文讨论的原因，某些操作（那些需要最新接触列表或需要将部件映射到单元空间中的操作）之前应先执行 清理模型对象命令（model clean） 命令。
  3. 循环计算期间： PFC 中的循环顺序旨在使模型在计算循环的每个时刻都保持清洁状态。 然而，PFC 的开放性和通用性意味着某些用户操作可能会使模型数据处于不一致状态。 例如，在计算过程中修改域范围或模型组成部分的尺寸即属于 这一类操作，因为它们可能影响接触列表。若此类操作在接触列表更新与 接触力更新之间执行，则结果可能与用户的预期不同。在这种情况下，建议使用 清理模型对象命令（model clean） 命令使模型 恢复到清洁状态。

…创建颗粒集合体

生成初始集合体是离散元（DEM）建模过程中至关重要的一步。事实上，将颗粒堆积成 一个连通的网络有无穷多种方式，所形成的堆积特征及其后续流变特性与建造历史密切相关。 因此，应当格外谨慎地构建与所研究问题的要求和规格相符的初始状态。

除规则（立方或六方）几何排列外，PFC 不提供自动创建连通颗粒集合体的内置工具。 它提供的是一组基本命令，可用于推导出适合所研究问题的高级算法：

  • ball create、clump create 和 clump replicate 命令可用于创建单个球颗粒或单个刚性团簇。请注意，鼓励用户在创建刚性团簇时 使用 clump replicate 并引用已有的刚性团簇模板（参见 刚性团簇模板创建（clump template create） 命令）。
  • ball generate 和 clump generate 命令可用于一次性生成指定数量且互不重叠的球颗粒或刚性团簇，方法如下。PFC 将尝试在 给定的尝试次数内生成指定数量的球颗粒/刚性团簇。对于每个待生成的球颗粒/刚性团簇，根据用户输入选取随机的尺寸和位置（仅对刚性团簇还需选取方向），然后 检查该候选球颗粒/刚性团簇是否与先前创建的球颗粒/刚性团簇重叠。如果未与已有球颗粒/刚性团簇重叠，则创建它； 否则将其拒绝，并进行下一次尝试。当达到指定的待生成球颗粒/刚性团簇数量或达到指定的尝试次数时，该过程停止。 在后一种情况下，会发出警告，说明实际生成的球颗粒/刚性团簇数量。
  • ball distribute 和 clump distribute 命令可用于在给定体积内分布球颗粒或刚性团簇，以在不进行重叠检查的情况下达到指定的固体分数，方法如下。 对于每个待分布的球颗粒/刚性团簇，根据用户输入选取随机的尺寸和位置（仅对刚性团簇还需选取方向），并不断添加候选球颗粒/刚性团簇，直至达到指定的固体分数。 由于该算法不防止重叠，生成的集合体处于不平衡状态，且较大的重叠会在最初的时步中产生很大的力，从而产生需要 从系统中移除的高动能。另外请注意，应谨慎使用 clump distribute 命令，因为刚性团簇之间的初始重叠可能导致刚性团簇相互咬合。

请注意，FISH 工具也可用于创建或修改球颗粒、刚性团簇以及墙体。

…设置和控制边界条件

通常有三种向 PFC 模型施加边界条件的方式：

  1. 使用墙体作为边界： 在 PFC 中，墙体不遵循牛顿运动定律。在某些情况下，墙体可以完全不动，例如充当固定容器。 然而，在其他情况下，用户需要对其运动学进行设定。例如，可以将切削工具建模为以恒定速度穿过颗粒集合体的墙体，或将搅拌机的叶片 建模为施加了转速的刚性墙体，而外部定子则建模为固定的刚性墙体容器。颗粒集合体施加在墙体上的反作用力 也可以被监测，并用于设计高级的伺服控制算法，以便调整墙体的运动，从而维持规定的应力边界条件。伺服控制算法的一个示例 在算例应用“探测颗粒试样（Probing a Granular Specimen）”中进行了描述。
  2. 使用颗粒作为边界： 可以标识模型中的选定颗粒，并控制其速度或对其施加外力。 例如，可以通过对边界颗粒施加力来模拟阻抗匹配边界，如算例 “颗粒集合体中的波传播（Wave Propagation in Particle Assemblies）”中所示。
  3. 使用周期性边界： 如果将模型域设置为在一个或多个方向上为周期性（参见 上一项（item above）），则 此条件将生效。

…控制初始条件

颗粒集合体中的初始条件通常源自其堆积历史以及所施加的边界条件。 例如，通常希望调整边界条件以建立相关的初始应力状态。取决于 所使用的接触模型（参见 下一主题（next topic）），用户还可能能够初始化 接触中的力和性质，以达到所需的初始应力状态。

…选择合适的接触模型

颗粒与其他颗粒以及与墙之间的相互作用，是通过发生在 接触（contacts）处的力来实现的。接触力学体现在采用软接触方法的颗粒相互作用定律中， 对于这种软接触方法，所有变形都发生在刚体之间的接触处。颗粒相互作用定律称为 接触模型（contact models）； 每个接触被分配单个接触模型。

尽管颗粒集合体可能表现出复杂的非线性本构行为，但这种行为通常是通过使用 相对简单的接触模型来实现的。PFC 提供了若干接触模型，其他接触模型可以 利用 C++ 插件（C++ Plugins） 附加功能来编写（详情请参阅“接触模型（Contact Models）”）。

接触模型分配表（CMAT）（Contact Model Assignment Table (CMAT)）已在 PFC 中引入，以简化选择接触模型的过程。该工具功能足够强大， 可以创建复杂的模型，例如使用多个接触模型并采用力学性质的非均匀分布。 建议用户参阅教程示例“使用 CMAT（Using the CMAT）”，以了解关于该主题的详尽讨论。

…标定材料行为

正如上文主题“…创建颗粒集合体（… create particle assemblies）”中所讨论的，离散体集合体的宏观力学行为与集合体的组构密切相关， 因而与其堆积历史相关。然而，给定堆积的力学行为显然也源自 模型微观参数的选择。PFC 将微观参数分为两类，属性和性质，如下所示：

  • 属性是模型组成部分的内在特征，例如位置、速度、尺寸、 等。体（球颗粒、刚性团簇和墙）、部件（球颗粒、刚性团簇、子颗粒和墙面片）以及 接触都可以具有属性。体/部件属性的一个例子是刚性团簇和子颗粒 的位置；尽管子颗粒是刚性团簇的一部分，但其位置是一个独立的属性。 属性列表是固定不变的（参见 ball attribute、clump attribute 和 wall attribute 命令）。
  • 另一方面，性质仅适用于接触和部件。 接触的性质取决于所使用的接触模型；每个接触模型定义一组 控制其本构行为的性质。接触性质可以用 contact property 和 contact method 命令来指定或修改。CMAT 也可用于 为新创建的接触指定接触模型和接触模型性质（参见 上一主题（previous topic））。 部件性质是用户用 ball property、clump property 和 wall property 命令指定的字符串/值对列表。这些字符串/值对表示 部件的表面条件。默认情况下，部件不含性质。接触模型可以用部件性质来确定 所产生的相互作用，这一过程通过 性质继承来实现。例如，如果要建模的物理试样 由 硬 和 软 球颗粒组成，则可以为这些球颗粒赋予不同的性质。 属性与性质之间的区别在“属性与性质（Attributes and Properties）”教程中进行了演示， 而性质继承机制的用法则在教程示例“使用 CMAT（Using the CMAT）”中进行了说明。

尽管向 PFC 模型赋予选定的属性和性质相对容易，但通常难以选择这样的参数，使其 能够代表真实材料。对于模拟连续体的代码（例如有限元或有限差分程序）， 输入参数（例如模量和强度）可以直接从 实验室试样的测量中导出。然而，PFC 在更基础的层面上工作；它从构成材料的 微观组分（等效颗粒和界面）中“综合”出材料行为。如果这些微观组分的力学性质和 几何形状已知，那么它们可以直接用作 PFC 的输入。这种方法称为“直接建模”。 但是，如果我们试图模拟固体（例如岩石），我们可能并不知道其 微观组分的力学性质。在这种情况下，我们必须使用“反演建模”（即对具有假定参数的试样进行若干 试验，并将结果与真实完整材料的期望响应 进行比较）。当找到匹配时，相应的参数集可以用于完整模拟。

…监测模拟

通常，了解模拟过程中相关量的演化而不只是 分析最终生成的状态是很有用的。在执行模拟步之前，建议用户确定那些 与所研究的具体情况相关的量，并启用记录其时间演化的机制。 在 PFC 中可以使用多种机制：

  • 历程： 历程机制（history mechanism） 允许在循环过程中周期性地（按指定的步间隔）记录变量的 值。PFC 提供了大量可使用该机制监测的内置 变量。CS：后续：构建“pfc 中可创建历程的命令列表”，将其放在主“历程”页面，然后在前一行中放入指向该列表的链接。 此外，还可以监测 FISH 变量的值或 FISH 函数的返回值， 或使用测量逻辑计算的值（见下文）。
  • 测量区域： 测量逻辑（measure logic） 可用于计算模型 {圆形（二维）；球形（三维）}区域上的平均量。这些量包括孔隙率、应力和应变率 张量、配位数以及颗粒尺寸分布。可以使用上文讨论的 历程机制按周期性的间隔对这些量进行采样。模型中可放置任意数量的测量区域。
  • 颗粒轨迹： 可启用 颗粒轨迹（Particle traces） 来按周期性的步间隔记录 模型组件的位置和速度。随后用户可以绘制所记录的颗粒轨迹，其中显示 被追踪对象的运动轨迹，并按速度大小着色。
  • SAV 文件： 用户可以使用 保存模型（model save） 命令周期性地将模型的中间状态保存到 SAV 文件中。 这些保存的状态可以在模拟完成后（使用 恢复模型（model restore） 命令）恢复，以便分析系统的中间 状态。SAV 文件包含整个模型数据，恢复的状态可以作为进一步 计算的起点（例如用于 顺序模拟（sequential modeling） 或参数敏感性分析）。然而，由于 SAV 文件 包含整个模型数据，它们通常很庞大，保存大量中间状态可能会消耗大量内存。 下文讨论的 模型结果文件 在只需要 周期性记录模型的选定信息时，可能是一个不错的替代方案。
  • 模型结果文件： model result 逻辑允许用户决定应周期性记录哪些附加于球颗粒、墙或刚性团簇的选定 信息。信息可以存储在程序内存中，或存储为若干二进制文件的形式（后者 可避免大量占用 RAM）。设置球体结果输出（ball results）、wall results 和 clump results 命令可分别用于为 球颗粒、墙和刚性团簇独立激活该逻辑。有关该逻辑的详细讨论，请参阅这些命令的 说明。示例“使用裂隙进行裂纹追踪的单轴压缩破碎分析（Fragmentation Analysis during a Uniaxial Compression with Crack Tracking Using Fractures）”演示了如何使用球颗粒结果逻辑在压缩 试验中记录球颗粒碎片 ID。请注意，在执行模拟步之前，必须激活模型结果逻辑并选择要记录的相关量。

… 求解至目标终止准则

有两个命令可用于执行模拟循环：执行计算时步（model cycle） 和 求解模型（model solve） 命令。执行计算时步（model cycle） 命令 用于执行给定数量的模拟步。尽管这在许多情况下很有用，但通常更可取的做法是 执行一段循环序列，直到满足相关准则，例如目标平衡条件或目标物理时间 （请记住，PFC 使用 自适应时步（adaptive timestep），其可能在循环序列过程中发生变化）。 求解模型（model solve） 命令更为复杂，接受一个或多个结束准则。 用户还可以实现自定义的 FISH 函数来判断计算应继续还是停止，并使用 FISH 中止（fish-halt） 关键字调用它。 更多细节请参阅 求解模型（model solve） 命令的说明。

… 执行顺序模拟

PFC 在处理顺序事件方面很灵活；几乎任何内容都可以在任何 阶段更改。例如，可以删除颗粒以模拟开挖。也可以 添加颗粒以模拟施工或充填空洞，但需要注意一些事项。 首先，如果新引入的颗粒与任何已有颗粒重叠，则在随后的循环中可能会产生 法向力，从而扰动已有系统（取决于所使用的接触模型）。如果向系统中 添加墙，也应注意类似的问题。 其次，如果需要新压密的集合体，压实过程应以尽量减少对 已有颗粒扰动的方式进行。例如，可以固定已有颗粒（速度为零），同时 使新颗粒膨胀以嵌入空洞。当达到平衡后，可以释放 对其余颗粒的固定条件（并继续进行循环以再次恢复 平衡）。

所有模型数据均通过 保存模型（model save） 命令保存到二进制文件中。之后可随时使用 恢复模型（model restore） 命令 还原这些数据。状态还原之后，可以修改模型并执行额外的循环，从而开展另一个 建模阶段，或例如进行灵敏度分析。

… 在计算循环中插入自定义操作

PFC 模拟由执行一系列循环组成，直至达到某个目标终止准则。每个循环 由按给定顺序执行的一系列操作组成，详见“PFC 模型表述（PFC Model Formulation）”一节。 用户可以借助 FISH 回调，在计算循环的特定位置插入自定义计算。 教程示例“使用 FISH 回调（Using FISH Callbacks）”详细论述了这一功能。
