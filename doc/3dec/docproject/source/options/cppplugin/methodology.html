方法

节理本构模型的基类

3DEC 对用户自定义本构模型的支持采用了 引言（Introduction） 中所述的面向对象编程方法。 由一个基类为实际的节理本构模型提供框架， 这些模型即从该基类派生的类。 该基类名为 JointModel，是一个“抽象”类。它声明了若干“纯虚”成员函数 （以附加在函数原型后的 =0 语法表示）。 这意味着不能创建该基类的任何对象， 并且任何派生类对象都必须提供实际的成员函数， 以替换 节理模型（JointModel） 的每一个纯虚函数。

JointModel 的完整文档见 程序员接口（Programmer’s Interface）。请参见 jmodels 命名空间。

成员函数

任何派生的本构模型类都必须提供实际函数，以替换 JointModel 中的虚成员函数。

模型类定义还应包含一个必须调用基类构造函数的构造函数。 在所有情况下，派生类构造函数都应以无参数方式调用，如 clone 成员函数所示。 数据成员的初始化可由构造函数完成，如此处所示。 在本示例中，符号 kn_、ks_ 等是派生模型的数据成员。

典型模型构造函数

  JModelExample::JModelExample() :     
    kn_(0),
    ks_(0),
    cohesion_(0),
    friction_(0),
    dilation_(0),
    tension_(0),
    zero_dilation_(0),
    res_cohesion_(0),
    res_friction_(0),
    res_tension_(0),
    tan_friction_(0),
    tan_dilation_(0),
    tan_res_friction_(0)
  {
  }

模型注册

每个用户自定义本构模型都编译为一个 DLL，该 DLL 必须在 3DEC 进程中实例化。 按照约定，作为 3DEC 插件使用的 DLL 中有四个导出函数： getName()、getMajorVersion()、getMinorVersion() 和 createInstance()。 还必须提供一个名为 DllMain() 的桩函数， 在从系统中加载和卸载该库时调用。 例如，对于示例模型，这些函数的形式如下：

int __stdcall DllMain(void *,unsigned, void *)
{
  return 1;
}

extern "C" __declspec(dllexport) const char *getName() 
{
#ifdef JMODELDEBUG
  return "jmodelexampled";
#else
  return "jmodelexample";
#endif
}

extern "C" __declspec(dllexport) unsigned getMajorVersion()
{
  return MAJOR_VERSION;
}

extern "C" __declspec(dllexport) unsigned getMinorVersion()
{
  return UPDATE_VERSION;
}

extern "C" __declspec(dllexport) void *createInstance() 
{
  jmodels::JModelExample *m = new jmodels::JModelExample();
  return (void *)m;
}

extern "C" __declspec(dllexport) 代码表示这些函数应从 DLL 中导出。

DllMain() 函数始终相同。

导出的 DLL 函数 getName() 应始终返回以 “jmodel” 开头的字符串。 这表明该 DLL 是节理本构模型插件。 在上面的示例中，导出的 DLL 函数 getName() 返回字符串 “jmodelexample”。 应遵循在导出名称前加 “jmodel” 前缀的约定。 JointModel 的 getName() 函数必须返回唯一的字符串 （这是用来区分不同本构模型的方法）。

不应改动 getMajorVersion() 函数。 主版本号由基础本构模型 DLL 确定， 并表示二进制兼容性。 按照约定，该编号也会体现在您所生成的 DLL 的文件名中。

getMinorVersion() 函数表示本构模型的次版本更新。 例如，若向本构模型添加了新属性， 它可能与旧版本在保存文件上不兼容。 在这种情况下，次版本号（定义于文件 “version.txt”）将增加 1。

createInstance() 函数实际创建并返回您所定义类的一个实例。 该实例存储在注册表中，并（通过 clone() 函数）用于创建所有其他实例。

循环计算过程中模型与程序之间传递的信息

3DEC 与用户自定义模型之间最重要的联系是成员函数 run(UByte dim, State *s)， 它在循环计算过程中计算模型的力学响应。 结构体 State（定义于 “state.h”） 用于向模型传递信息以及从模型传出信息。

State 的完整文档也见于 程序员接口（Programmer’s Interface） 文档的 jmodels 命名空间中 （可从屏幕上的 帮助 菜单获得）。

成员函数 run() 的主要任务是由位移增量计算新的力。 在非线性模型中，传递模型的内部状态也很有用，以便该状态可被绘制和打印。 例如，随附的模型会指出它们当前是否正在屈服或过去是否曾屈服。 每个子接触可设置变量 state_， 它以一系列可开可关（1 或 0）的位来记录模型的状态。 每一位都可与一条显示在屏幕上的消息相关联。 成员函数 States 返回的字符串包含若干子串，分别对应于模型可在 state_ 中设置的位位置。 第一个子串对应第 1 位，第二个对应第 2 位，依此类推。 可以同时设置多个位。 例如，剪切屈服和拉伸屈服可能同时发生。 各位的分配如下所述。 查阅任一非线性模型文件（例如 “jmodelexample.cpp”）即可理解状态逻辑的运行方式。

数组 working_ 和 iworking_ 可将数据安全地存储在 State 结构中。注意，用户不应假定这些数组在首次调用第一个四面体时已被初始化为零，而应自行检测并初始化该存储。

子接触的状态指示变量

每个子接触 State 都有一个 state_ 成员，可用于存储破坏状态。 该成员变量有 32 位，最多可表示 16 个不同状态（假定您分别跟踪“当前”和“过去”状态）。 内置本构模型使用状态指示位来表示子接触的塑性破坏。 关于内置本构模型的位分配及相应的破坏状态，见 表 1（Table 1）。注意，这只是一项约定，并非所有本构模型都实际要求如此。

对于用户自定义本构模型， 用户可以创建一个命名状态并为该状态指定任意一个特定位， 随后更新子接触的状态指示变量。 表 1（Table 1） 中的命名状态由内置本构模型用来 更新子接触的破坏状态， 并展示了状态指示变量的一种具体用法。

3DEC 对每个子接触调用本构模型函数 run()， 以更新其力的取值。 通常，本构模型在该过程中还会更新状态指示变量。 对于内置模型，状态指示变量表示子接触的破坏状态。 本构模型通过对子接触状态指示变量与本构模型计算得到的当前破坏状态 执行逻辑“或”(|) 运算来更新它。 用户应注意正确设置或清除此前已更新的所有状态， 使其先于本构模型计算得到的当前状态。 随后，可用状态变量与所需的用户自定义状态 通过逻辑“与”(&) 运算符检查子接触的状态。

假设某个子接触正在发生拉伸破坏和剪切破坏。 该破坏状态存储在子接触的状态指示变量中。 内置本构模型对状态变量进行更新：

  1. 首先检查当前状态，并相应地设置/取消设置状态指示变量。例如，
    if (s->state_ & slip_now) s->state_ |= slip_past;
    s->state_ &= ~slip_now;
    if (s->state_ & tension_now) s->state_ |= tension_past;
    s->state_ &= ~tension_now;
  1. 计算子接触的当前状态。
  2. 必要时更新状态。例如，
      s->state_ |= tension_now;

在初始化（步骤 a）中，slip_past 和 tension_past 被置位，shear_now 和 tenison_now 被清除。 步骤 (c) 为该特定子接触设置第 2 位（tension_now）。 假定过去没有发生破坏，FISH 函数 子接触状态（block.subcontact.state） 返回值为 2， 即第 2 位置位所对应的十进制值。
