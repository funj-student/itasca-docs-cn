保存

模型状态

在建模工作期间的任何时候，都可以使用多种方法保存模型的状态。包含已保存模型状态的文件可互换地称为保存文件、保存或已保存状态，或 SAV 文件（从历史上看，已保存模型状态文件使用 .SAV 文件扩展名）。

保存模型状态是一个重要且富有技巧性的过程——其执行方式如何，能有效地体现项目设计。数值建模项目需要在时间步进（timestepping）过程中逐步构建模型，但程序只能表示当前计算循环状态下的模型。因此，一个项目几乎总会包含多个保存文件，它们就像踏脚石一样，勾勒出建模项目所走过的路径。回顾“数据文件的工作方式（How Data Files Work）”可知，可以认为建模过程很可能（或应该）生成一组保存文件，这些保存文件反映了构建它们的数据文件的层次结构：数据文件的树状链接创建了项目，而保存文件的树状链接也很可能由此产生。

项目与模型状态

有关保存项目的基础知识，请参见 处理项目（Handling Projects）。

程序内的文件变更——无论是打开新文件、关闭当前文件，还是打开另一个已存在的文件——如果当前文件处于未保存状态，都可能引发一些提示。鉴于程序中处于活动管理下的文件种类繁多（项目文件、保存文件、结果文件、数据文件等），可能出现的情形有许多种组合，而考虑到程序中处于活动管理下的文件数量，这些情形很容易被触发。在这些情况下，一个对话框或一系列对话框将向用户提供处理未保存数据的选项。

结果文件

结果文件是仅包含选定模型数据的保存文件，比完整保存文件更小，有时小得多。它们在计算循环之前通过命令或从 i 选项（Options） 对话框请求生成。结果文件的恢复方式与保存文件相同，即恢复后结果文件将成为当前模型状态。但是，无法从该状态进行循环计算；就此而言，结果文件是“只读”的。

结果文件是一种便利手段，在以下情形中具有优势。

  • 它们可以在运行期间对模型提供更细粒度的跟踪，因为它们代表了模型的第二条数据流，而这条数据流很可能比保存文件所创建的数据流更细粒度。
  • 如果模型足够大，以致恢复各个模型状态很耗时，那么在后处理分析期间，结果文件可以提供一种在模型状态之间切换的快得多的方式。
  • 如果需要将模型运行某一段过程中的模型输出导出到其他工具（用于制作动画、电子表格等），并且所有必需的数据都能事先确定并请求生成，那么从结果文件进行导出通常更容易也更快捷。程序提供了一个工具（provides a tool），用于批处理结果文件以制作动画。
