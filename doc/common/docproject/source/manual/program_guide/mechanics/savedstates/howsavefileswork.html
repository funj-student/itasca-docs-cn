保存文件的工作方式

当前模型数据和模型保存文件是程序的基本“素材”：跟踪模型数据以及打开和关闭保存文件正是程序所做的工作。

一次只能有一个模型状态处于活动状态。恢复一个保存文件会关闭当前的保存文件。如果在请求恢复另一个保存文件时当前状态存在模型更改，程序将提示用户根据需要保存当前状态。

i 项目（Project） 窗格允许在保存文件之间快速切换。在“已保存状态”列表中双击某个项目项，会对该文件执行 恢复模型（model restore），使程序处于该模型状态。

建模项目往往取决于少数（或一个）关键模型状态。将模型恢复到该状态的能力，便成为实现建模项目目标的基础。例如，参数研究通常是对同一个已保存（并恢复）的状态多次进行改动，以确定对正在研究的参数的敏感性。设计研究可能会将模型恢复到某一时点，然后“分支”一次以考察安装结构支护后的结果，再分支一次以考察无支护时的模型。反分析可能会反复将模型恢复到某个已保存的破坏前状态，以研究若干可能的破坏机制。

保存文件剖析

保存文件是一个二进制文件*，其中包含已保存的模型状态（model state）。它可能被压缩，也可能不被压缩（详见 保存模型（model save） 命令）。

保存文件包含一个基于文本的文件头，其中封装了有关该文件来源以及用于生成它的命令/输入的信息。保存文件的主体以二进制形式包含完整的模型状态信息，包括以下内容。

  • 所有模型对象以及随它们存储的所有自定义数据（存储在额外变量中）
  • 所有辅助实体（几何体、DFN 等）
  • 所有中间模型对象（FLAC3D 中的拉伸集和构建块集、PFC 中的块体模板等）
  • 所有当前的 FISH 符号和值

当使用 新建模型（model new） 命令清除模型状态时，上述所有内容都会从内存中被完全清除。

记住这一点很有用，它可以用来区分哪些内容不会随模型状态一起保存，因而要么记录在 项目文件（project file） 中，要么可能是持久的程序设置。

注意

*可以选择将文件保存为基于文本的 JSON 格式。这样会产生很大的文件，读写速度较慢，但其优点是其他应用程序可以访问其中的数据。
