项目：进一步说明

项目文件是 5.0 版中新增的。对于 4.0 或更早版本的用户而言，它代表了建模运行组织方式的重大转变。项目文件是一个二进制文件，它跟踪（但不嵌入）建模序列中使用的资源。在本文档中，这些资源通常被统称为“项目项”，它包括以前版本用户所熟悉的所有文件类型：数据（.dat）文件、保存（.sav）文件、FISH（.fis）文件和驱动（.dvr）文件。程序运行期间始终有一个项目处于打开状态，它要么是用户请求新建的项目，要么是用户已打开的先前保存的项目，要么是在用户未指示执行前两种操作的情况下程序创建的“临时”项目。

程序会自动将项目文件所在位置设为当前工作目录。这使得保存项目项更加容易，并无需使用显式路径或发出设置当前文件夹的指令即可将项目项保持在一起。访问文件系统的对话框（保存…、打开… 等）在使用时会将包含项目文件的文件夹作为默认位置呈现。

组成活动项目的项目项及其当前状态（已保存、未保存、已打开、已关闭或缺失）列在 项目 窗格中。希望熟悉项目及其工作方式的用户，最好多关注 项目窗格（Project pane） 的状态，因为它提供了项目本身的图形化表示。

项目跟踪建模中使用的所有项目项。项目项进入项目的方式有三种：（1）由用户手动加载（例如，使用文件菜单打开数据文件）；（2）直接在 PFC 中创建（例如，创建新的数据文件，或在控制台命令行保存模型状态）；或（3）在命令处理过程中创建/添加（例如，在数据文件中发出 保存模型（model save） 命令，或当前正在处理的数据文件调用数据文件（program call）另一个数据文件时）。

同样，可以使用 项目 窗格从项目中删除项目项。用户应记住关闭项目项（仅将其从 PFC 界面中移除）与移除或删除项目项（不仅将其从项目中剔除，还会删除与该项目的关联文件）之间的区别。

最后，有经验的用户此时会注意到，项目中跟踪的所有项目项本身都是与项目文件不同的文件。由于这些文件的位置是项目所监控的内容的一部分，因此在 PFC 之外操作这些文件（特别是移动或重命名它们）有可能在项目内引入错误或失效链接。
