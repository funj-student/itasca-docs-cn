项目与项目项跟踪

项目文件和项目项（数据文件、已保存状态等）可以保存到任何位置。它们不必保存在同一位置。项目文件会跟踪所有项目项的位置。

就文件与文件存储而言，所有项目管理的核心在于当前工作目录这一概念。任何时候，程序都有一个用作当前工作目录的特定路径。这有两个关键影响。

  • 程序请求的任何项目项（例如，通过 调用数据文件（program call） 或 恢复模型（model restore） 命令请求）都将在当前工作目录中查找，除非显式给出了该项目项的完整路径。
  • 程序要保存的任何项目项（同样，例如通过 保存模型（model save） 或 导出绘图（plot export） 等命令）都将保存到当前工作目录，除非显式给出了该项目项的完整路径。

上述说明涉及命令。在用户界面中操作时（例如，使用 文件 -> 打开项目项… 对话框），当前工作目录将是调用任何文件处理对话框时最初呈现的文件夹。

默认情况下，程序将包含项目文件的文件夹用作当前工作目录。

鉴于以上信息，在处理项目及其跟踪的项目项时，还值得记住以下补充说明。

打开项目文件夹之外的项目项

使用 文件 -> 打开项目项… 命令带入项目的项目项不会被移动或复制到包含项目文件的文件夹中。如果用户希望采用将所有项目项都存储在项目文件同一位置的文件夹处理方案，应在使用“打开项目项…”将其打开到项目之前，先将任何现有的待用项目项移动到项目文件文件夹中。

关闭项目时保存文件

当前，关闭项目时会保存所有打开的项目项。如果用户打算在外部编辑器中处理数据文件、同时在程序中编辑这些文件，应意识到这一点。

注意

关于程序之外的文件处理

在程序之外使用其他工具（例如，使用 Windows 资源管理器文件浏览器）移动、重命名或删除某个项目项，会在使用该文件的任何项目中破坏与该文件的链接。

在程序之外对数据文件所做的编辑，会在焦点返回到包含该文件的编辑器窗格时反映到程序中该文件已打开的实例中，前提是进行编辑时该文件处于已保存状态。如果该文件不处于已保存状态（即，已在程序中对它做了更改但尚未保存），则会弹出一个警告对话框，要求用户决定如何处理该文件。
