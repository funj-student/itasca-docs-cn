绘图文件

绘图文件是给定绘图的 JSON 格式文本描述。请记住，程序内的绘图不会单独存储在文件中；它随项目一起保存，因此绘图文件必须显式创建，并且存在于项目之外。以这种方式保存绘图主要有两个原因：在不同的项目中重复使用，或访问用于构建该绘图的命令/关键字（参见 TOPIC）。

纳入模型

在当前项目中打开绘图文件只有一种方法：

  • 通过 c 文件 —> 打开（File —> Open） 对话框。

注意

没有命令可以将 *.plt 文件打开到项目中；该操作只能通过界面工具完成。

创建绘图文件

创建绘图文件有两种方法：

  • 通过要保存的绘图工具栏上的“保存”按钮（ ）
  • 通过 File —> [plot name] —> Save As... 菜单命令（其中 [plot name] 是活动绘图的名称，显示在其标题栏上）

注意

没有用于保存 *.plt 文件的命令；该操作只能通过界面工具完成。

绘图文件与绘图数据文件

程序提供两种存储绘图的方法。这里所述的绘图文件是对当前绘图的基于文本的 JSON 描述。文件中找到的描述将与该绘图在项目文件（*.prj）中的描述完全相同。绘图数据文件包含用于创建给定绘图的完整命令集。这两种文件都不会由程序自动创建；都必须由用户显式创建并保存。

从功能角度看，保存绘图（*.plt）文件与保存绘图数据（*.dat）文件之间存在大量重叠。

  • 两者都是存储给定绘图的方式，使其独立于项目存在（见上文）。
  • 两者都可用于在一个项目中重建先前在另一个项目中构建的绘图。
  • 两者都可以通过解读（*.plt）或读取（*.dat）来查看构建给定绘图时用到了哪些命令。
  • 两者如果被引入新项目，相对于新项目的当前模型状态，可能合理，也可能不合理。

基于以下原因，人们可能会优先选用其中一种而非另一种。

  • 绘图数据文件与任何 *.dat 文件一样，可使用 调用数据文件（program call） 命令被call。因此，这些文件可以并入模型运行的调用栈；绘图文件则不能。如果需要在运行过程中构建绘图，则优先使用绘图数据文件。
  • 如果需要在模型运行过程中进行动态绘图操作——即使用 FISH 或 Python 编写绘图过程的脚本——用户可能会发现，使用绘图文件比使用数据文件更容易识别出希望在脚本过程中操作的开关。本文档提供了用于创建和操作绘图的 c 绘图（plot） 命令，但没有提供用于配置 绘图项 外观的命令。这就是用户可能有兴趣使用绘图文件或绘图数据文件来查看它们的原因（更多信息请参见 命令驱动的绘图工作流（Command-Driven Plotting Workflow） 主题）。
